# 自动六面加速度计校准

2026-10-01。固件与当前网页上位机的代码已实现。初次交付验证使用原生测试和模拟串口；后续主代理已按用户授权烧写并开展实际摆板验证，已观察到六面识别、重复面提示、等待超时与六面采齐后的拟合失败。成功保存与校正精度仍待实测确认。

## 使用流程

1. 连接 USB CDC 或 UART，进入设备设置模式。
2. 点击“开始六面校准”。依次让传感器 X、Y、Z 轴竖直向上和向下，共六个方向，顺序不限。
3. 每面使用平稳支撑，摆正后保持静止约 1.5 秒。当前方向高亮，完成的面出现勾选。
4. 六面采集完整、拟合检查通过且 Flash 写入回读成功后，才显示“校准完成，已保存”。校准立即作用于随后采样，重启后重新加载。
5. 点击“取消校准”或退出设置模式，会丢弃本次未保存的采样，保留原参数。断开上位机不会隐式取消设备任务；重连后读取状态，设备等待下一面超过 60 秒会自行退出。

界面位于 `upper/gyro-live/src/public/`，本地构建产物位于 `upper/gyro-live/dist/public/`，诊断界面资源版本为 `20261001acc3`。`tools/web_host/` 是另一套旧实验界面，本次没有用新界面覆盖它。启动命令保持兼容，完整进度与取消操作使用当前网页上位机。

## 实测诊断界面

在已有 60 字节状态帧中直接读取 `raw_g[3]`，显示 X/Y/Z 原始加速度和模长，并说明当前采样方向的理想摆正参考：该轴约 ±1 g、其余两轴约 0 g。设备识别到的面用“设备识别”标示；未识别时，用主轴 g 值推断的方向明确标为“按 g 值估计”。正面表示该传感器轴正方向朝上，负面表示正方向朝下。原始数据仍带零偏，理想参考只帮助摆放，不作为上位机新增的通过阈值。

仅在校准运行且状态帧未超过 3 秒时将数值标为当前读数；停止、失败、断开或状态停更时，保留最后数值并标明“非实时”。没有有效读数时显示等待采样。

运动/倾斜提示补充用平整支撑固定、微调使其他两轴接近 0 g 的操作步骤。相同状态也可能来自角速度、加速度变化或采样间断，原始三轴 g 不能单独确定原因，因此不会凭该提示判定传感器有故障。`0x0606` 补充说明六面已采齐但拟合出的零偏或比例超出合理范围、未保存，并说明轻微倾斜已自动补偿、不是失败原因；当前状态帧没有失败面的均值、残差或具体拟合检查项，不能据最后一个 raw_g 推断某一面失败。

此诊断更新没有修改固件、协议或校准阈值。网页 51 项单测、11 组模拟串口界面检查通过，包括正负方向、原始数值、参考方向与识别方向的区分、终态非实时标记及失败指导。实际板上失败原因需结合六面采样数据继续核对。

## 采集、拟合与坐标

`src/calibration/acc_six_face.c` 是独立、无硬件依赖的状态机。校准使用 LSM6DSV 原始传感器坐标，输入为尚未加校准的 nominal g；静止判断使用温度及零偏修正后的角速度 deg/s。位序和方向固定为：`−X、+X、−Y、+Y、−Z、+Z`。使用传感器轴判断方向，不从上位机的 Pitch/Roll 画面反推姿态。

- 每面连续稳定 500 ms，再连续采样 1000 ms；只把采样阶段的数据用于拟合。
- 陀螺仪三轴绝对值均不超过 2 deg/s，加速度模长在 0.85~1.15 g，主要轴至少 0.75 g，其余轴不超过 0.20 g。
- 任意样本非有限、姿态变更、运动、加速度单步变化超过 0.025 g，或相邻采样间隔超过 20 ms，都会清除当前候选、计时、均值和方差。之前完成的面保留。
- 每面至少 50 个样本，各轴样本标准差不超过 0.015 g。方差检查失败重新等待当前面，不保存不稳定结果。
- 已完成方向不重复计数，也不以新的同面数据覆盖旧的已完成面。等待下一面 60 秒超时，计时在每面完成后重新开始，并支持毫秒计数回绕。

拟合采用轴对齐椭球模型：求每轴零偏和比例，使六个面的校准后重力模长都等于 1 g。手持摆放的倾斜只改变重力方向，不改变模长，因此每面的离轴分量 `off` 被折算进主轴目标 `t = sqrt(1 - off²)`，不再当作误差拒绝。每轴由正负两面求解 `scale = (tp + tn) / (P - N)`、`bias = (tn·P + tp·N) / (tp + tn)`，再用新参数重算各面离轴分量与目标，固定迭代 8 次（每次误差约缩小离轴分量平方倍，远快于浮点精度需求）。完全摆正时 `tp = tn = 1`，退化为原公式 `bias = (P + N) / 2`、`scale = 2 / (P - N)`。

通过条件：零偏绝对值不超过 0.15 g，比例在 0.85~1.15，六面校准后模长与 1 g 偏差不超过 0.001 g（收敛检查），离轴分量不超过 0.50 g（仅作数值保护，实际倾斜已由每面识别的 0.20 g 门限约束）。未通过时整次校准失败，不改变当前校准。

**2026-10-01 修订**：首次实板测试六面采齐后返回 `0x0606`。原拟合要求校准后离轴分量残差不超过 0.06 g（约 3.4°），而每面识别允许离轴到 0.20 g（约 11.5°），两者不一致；板卡立边放置时倾斜 3.4°~11.5° 即可通过识别却必然拟合失败。在识别门限内，正负跨度条件无法被触发；零偏超过 0.15 g 或比例超过 1.15 需要传感器零偏或灵敏度误差远大于正常器件，因此该失败最可能来自倾斜残差（由代码分析得出，尚未用失败时的六面均值实测确认）。改为上述模长模型后，倾斜摆放可精确求解；`0x0606` 只在比例或零偏确实超出合理范围时出现（例如某轴灵敏度偏低约 14%）。

校正公式沿用 `(nominal_g - bias_g[axis]) * scale[axis]`，先校正，再换算为 m/s²，作用于启动重力估计和运行融合的已有转换位置。原始 nominal g 诊断保持原义，算法输入及输出的既有单位不变。该方法拟合三轴零偏和对角比例，不拟合安装角、非正交、交叉轴耦合或温度模型。六面采集本身不是独立精度验证；真实摆放与额外斜置姿态仍需验证。

采集不阻塞 2 kHz 循环。保存安排在 `service_tasks`；写 Flash 后沿用现有采样暂停和时间基准重建处理，避免把写入暂停误当作正常 500 µs 采样间隔。六面校准功能默认编译启用，仍由用户点击开始，不在每次开机自动执行；可通过 `APP_ACC_CAL_ENABLE=0` 构建关闭版。

## 持久化与掉电行为

仅使用加速度校准原扇区 `0x0803C000..0x0803C7FF`，不动 Bootloader、应用、设备设置、陀螺零偏或升级状态预留区。支持旧 v1 记录读取和新 v2 追加记录。

v1 记录保留原 36 字节布局：magic、version=1、bias[3]、scale[3]、CRC。v2 为 64 字节追加槽，整个扇区可容纳 32 个槽；旧 v1 占用首槽时，还可使用后面的 31 槽。

| v2 偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 4 | magic `0x41434332` |
| 4 | 4 | version = 2 |
| 8 | 4 | sequence，递增，支持 uint32 回绕比较 |
| 12 | 12 | bias_g[3]，float32 |
| 24 | 12 | scale[3]，float32 |
| 36 | 20 | reserved[5] = 0 |
| 56 | 4 | CRC，覆盖偏移 0..55 |
| 60 | 4 | commit `0x41434F4B`，最后写入 |

所有字段按 MCU 小端存储。**v1/v2 校准记录 CRC 都保留旧的未取反约定**：反射多项式 `0xEDB88320`，初值 `0xFFFFFFFF`，结束不执行 final XOR。它与常见 `zlib.crc32`、升级镜像常用 CRC32 的末尾处理不同，不能直接混用。

保存选择完整空白槽，顺序写前 60 字节，再写最后的提交字；最后回读记录、校验 CRC 和全部内容，成功后才替换 RAM 中的活动参数。不调用扇区擦除。部分写入或掉电产生的未提交槽不会激活，也不会再次使用。重新启动会加载最新完整有效记录；新槽损坏时仍可读取先前有效记录或 v1。

**满槽返回 `-4`/错误 `0x0609`，不擦除扇区，不覆盖最后有效值。** 单扇区不能在擦除过程中同时保证原值仍持久存在，因此本次不做自动清理。维护时需先导出备份，再由维护流程清理并恢复；本次没有实现或执行此维护操作。重复保存与当前有效参数完全相同的结果无需新槽。

加载时，v1/v2 参数均要求有限数、零偏绝对值不超过 0.15 g、比例严格在 0.5~1.5 且 CRC/提交标记合法。历史记录若超出此安全范围按无效处理；没有有效记录时使用零偏 0、比例 1。新拟合比历史读取范围更严格，兼容已有合理的校准记录。

## USB/UART 协议

沿用 AA55 帧和 CRC16，既可混入 JustFloat 输出，也可在不启用普通遥测时回复。进度发送到启动校准的接口，运行时最多每 200 ms 一帧；两端均可查询或取消。

| 命令/消息 | ID | 含义 |
|---|---|---|
| START_ACC_6FACE_CAL | `0x1C` | 空负载；要求设置模式；成功开始 ACK detail=`0x0100`；已在运行返回 `0x0604` |
| QUERY_ACC_CAL | `0x24` | 空负载；回复校准状态，可用于重连恢复界面 |
| CANCEL_ACC_CAL | `0x25` | 空负载；取消待完成采集并回读；未在运行时是幂等操作 |
| ACC_CAL_STATUS | `0x0A` | 60 字节 v1 状态负载 |

设备 CONFIG 的 capabilities bit 7 表示自动六面校准已编译启用。`0x23` 命令和 `0x09` 消息继续留给升级设计的固件身份查询。

| 状态负载偏移 | 字段 |
|---|---|
| 0..7 | version=1、status、phase、detected_face、face_mask、enabled、valid、reserved=0，各 uint8 |
| 8 / 10 | progress_permille / error，各 uint16 |
| 12 / 16 / 20 | 当前面 samples / 本次 elapsed_ms / 本面等待 remaining_ms，各 uint32 |
| 24 / 36 / 48 | 当前有效 bias_g[3] / scale[3] / 原始 raw_g[3]，各 float32[3] |

status：0 空闲、1 进行、2 完成且已保存、3 失败、4 取消。phase：0 等待、1 稳定确认、2 采样、3 待保存、4 完成、5 运动/摆放不合格、6 重复面、7 失败。detected_face：0 无候选，1..6 为上文位序；face_mask 低六位表示已经完成的面。每个稳定/采样阶段的 progress 为 0..1000，界面只解释为当前阶段进度，不把传输或采集完成当作保存成功。

错误 detail：`0600` 未启用、`0602` 不在设置模式/参数错误、`0603` 等待超时、`0604` 已在运行、`0605` 样本不足、`0606` 拟合未通过、`0607` 保存失败、`0608` 已取消、`0609` 日志满。成功结束仍回复原启动命令的 ACK，并发送终态；若终态在串口中丢失，上位机检测状态停更并查询恢复，不重复自动启动。
