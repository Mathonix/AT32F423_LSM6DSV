# 上位机交接：静置初始化 VQF 参数

这次固件增加“静置 60 秒初始化 VQF 参数”，以及“恢复默认 VQF 参数”。网页源码还没改，也不要部署。九轴应用已于 2026-10-02 用 4 MHz SWD 烧到板上。旧固件不认识 `0x29` 到 `0x2D`，会回 ACK `status = 0x01`。

不要改已保存的融合模式、滤波档、陀螺量程、快速启动、输出速率和 CAN。不要改零角速保持的阈值。静置初始化只覆盖下面写明的几项。

## 默认值从哪来

唯一来源是固件编译进程序的当前参数。上位机不要再写一份数字。

界面上的“当前值”和“默认值”都用设置帧 `0x0E` 里的字段。`default_*` 四个数永远是固件现在这组宏，和有没有做过静置初始化无关：

| 字段 | 当前固件 |
| --- | --- |
| default_sigma_init_dps | 0.50 |
| default_sigma_rest_dps | 0.035 |
| default_rest_gyr_dps | 0.60 |
| default_rest_acc_ms2 | 0.15 |

这四个数如果以后改宏，上位机不用改。以设备回读为准。

下面这些不参加静置初始化，也不参加这次恢复，继续跟滤波档或现有固件配置走：

- `tauAcc`、`restFilterTau`（0.5 s）、`restMinT`（1.0 s）
- 零偏遗忘时间、零偏限幅
- 运动零偏开关、运动零偏 sigma、垂直遗忘
- 零角速保持的六个阈值

## 参数来源

`0x0E` 的 `source`：

| 值 | 界面 |
| --- | --- |
| 0 | 默认参数 |
| 1 | 静置初始化 |

`source = 0` 时，`bias_dps` 是此刻 VQF 正在用的零偏，不是 0。`calibration_temp_c` 为 0。四个当前阈值和 sigma 等于上面的默认值。

`source = 1` 时，`bias_dps`、两个 sigma、两个静止门限和 `calibration_temp_c` 是 Flash 里那次静置结果。运行中 VQF 仍会继续跟踪零偏，实时零偏看原来的 `0x09` / `0x0C`，不要把 `0x0E` 的 bias 当成每一拍的实时值。

`cal_valid` 与 `source` 相同：1 表示当前采用的是一条有效静置记录。

## 静置成功后会改什么

只改这五项：

- 三轴陀螺零偏
- `biasSigmaInit`
- `biasSigmaRest`
- `restThGyr`
- `restThAcc`

另外记下标定温度和噪声统计，供失败原因和复查使用，不单独给上位机逐项编辑。

安静采集不会把静止门限和静止 sigma 调得比现在更小。下限就是当前固件值。所以一次很安静的成功结果通常是：

| 项 | 结果 |
| --- | --- |
| restThGyr | 0.60 °/s，停在下限 |
| restThAcc | 0.15 m/s²，停在下限 |
| biasSigmaRest | 0.035 °/s，停在下限 |
| biasSigmaInit | 0.10 °/s |

只有噪声更大、但仍然通过检查的采集，才可能把 `biasSigmaRest` 抬到 0.035 和 0.06 之间。静止门限的上限是 1.20 °/s 和 0.40 m/s²，能通过噪声检查的采集一般到不了这个上限。

成功后立刻作用于正在运行的 VQF，不重建姿态，也不把陀螺输入清零。换滤波档时，`tauAcc` 仍跟档位走，静置得到的两个静止门限会再写回去，避免档位表里的 0.6 / 0.15 把它们盖掉。

## 采集过程

点开始之后先等连续静置 5 秒。这 5 秒不进统计。中间如果动了，5 秒重新计，不算失败。从点击起超过 120 秒还没进入正式采集，判失败，原因是移动。

正式采集按墙上时间 60 秒，不按固定采样个数。采样率仍是 2 kHz。采集中一旦明显移动就立刻失败，这次统计丢掉，不写 Flash，正在用的参数不变。

明显移动的门槛是角速度模长大于 2.0 °/s，或加速度模长偏离重力超过 0.8 m/s²。这和生成出来的静止门限不是同一个数。

进度帧里的 `gyro_rate_dps` 是角速度模长，`acc_deviation_ms2` 是加速度模长相对 9.80665 的偏差，用来判断放得稳不稳。

## 失败原因

`0x0D` 的 `error`。成功时为 0。失败时界面要写出具体原因，不要只写“失败”。

| 值 | 含义 |
| --- | --- |
| 0 | 正常 |
| 1 | 采集前一直没放稳，或采集中移动了 |
| 2 | 陀螺噪声过大 |
| 3 | 加速度噪声过大 |
| 4 | 零偏超出 ±2 °/s |
| 5 | 60 秒内温度变化达到或超过 2 °C |
| 6 | 零偏在 60 秒内仍明显漂移 |
| 7 | 有效样本不够 |
| 8 | 出现非法数值 |
| 9 | 校验通过，但 Flash 写入失败。旧记录保留，运行参数不变 |

状态 `state`：

| 值 | 含义 |
| --- | --- |
| 0 | 空闲 |
| 1 | 等待放稳 |
| 2 | 预稳定计时中 |
| 3 | 正在采集 60 秒 |
| 4 | 正在检查，通常一闪而过 |
| 5 | 成功 |
| 6 | 失败 |

`elapsed_ms` / `remaining_ms`：预稳定阶段剩余时间含后面的 60 秒；采集阶段只倒计时这 60 秒。结束后剩余为 0。

## 协议

帧仍是 `AA 55`，CRC16-CCITT，小端。载荷最长 64 字节。

旧固件收到这些命令会回 ACK，`status = 0x01`（未知命令）。这时隐藏开始、取消和恢复默认，不要当成已经执行。查询若 3 秒内没有对应数据帧，也按不支持处理。

必须先 `0x17` 进入设置模式，才能开始或恢复默认。未进入时 `status = 0x03`，`detail = 0`。载荷不是空的时候 `status = 0x02`。

取消不需要设置模式。查询也不需要。

### 状态 `0x0D`，28 字节

查询命令 `0x29`，空载荷。只回这一帧，不回 ACK。序号用命令的序号。

采集过程中，设备大约每 200 ms 主动发一帧，序号为 0，只发给当初点开始的那个口。结束时再发一帧，序号也是 0。不要只看 ACK 判断结束。

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | uint8 | version，固定 1 |
| 1 | uint8 | state |
| 2 | uint8 | error |
| 3 | uint8 | source，0 默认，1 静置初始化 |
| 4 | uint32 | elapsed_ms |
| 8 | uint32 | remaining_ms |
| 12 | uint32 | sample_count，只计正式采集 |
| 16 | float | gyro_rate_dps |
| 20 | float | acc_deviation_ms2 |
| 24 | float | temperature_c |

### 开始 `0x2A`

空载荷。成功时先 ACK（`detail = 0`），再一帧 `0x0D`，序号都用命令序号。

| 情况 | ACK status | detail |
| --- | --- | --- |
| 成功 | 0x00 | 0 |
| 已经在做，或六面校准还在进行 | 0x03 | 0x0701 |
| 主循环还没开始（上电采集零偏期间） | 0x03 | 0x0702 |
| 没进设置模式 | 0x03 | 0 |
| 载荷不是空的 | 0x02 | 0 |

失败时不要把界面切成“正在采集”。

### 取消 `0x2B`

空载荷。先 ACK，再一帧 `0x0D`。统计清掉，回到空闲。不写 Flash，不改当前参数。

### 设置 `0x0E`，52 字节

查询命令 `0x2C`，空载荷。只回这一帧，不回 ACK。

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | uint8 | version，固定 1 |
| 1 | uint8 | source |
| 2 | uint8 | cal_valid |
| 3 | uint8 | 保留，0 |
| 4 | float[3] | bias_dps |
| 16 | float | bias_sigma_init_dps，当前值 |
| 20 | float | bias_sigma_rest_dps，当前值 |
| 24 | float | rest_th_gyr_dps，当前值 |
| 28 | float | rest_th_acc_ms2，当前值 |
| 32 | float | default_sigma_init_dps |
| 36 | float | default_sigma_rest_dps |
| 40 | float | default_rest_gyr_dps |
| 44 | float | default_rest_acc_ms2 |
| 48 | float | calibration_temp_c |

成功结束时，除了 `0x0D`，还会再发一帧 `0x0E`，序号为 0。失败不发 `0x0E`，因为参数没变。需要的话可以自己再查 `0x2C`。

### 恢复默认 `0x2D`

空载荷。建议先问一句：恢复后，这次静置结果会清除。

成功时先 ACK（`detail = 0`），再一帧 `0x0E`。`source` 变为 0。Flash 里的静置记录作废，下次上电不会再把它读回来。

恢复立刻把两个静止门限和两个 sigma 设回 `default_*`。不会把零偏写成 0。

- 这次上电曾经点过开始：零偏回到那次开始之前的值。
- 这次上电只是读到了以前的静置结果，中间没有再点开始：零偏数字先留着，门限和 sigma 已经是默认。下次重启没有静置记录，会走原来的开机采集。

Flash 写失败时 `status = 0x03`，运行参数和 Flash 记录都不变，随后仍回一帧 `0x0E`，用它确认还是原值。

正在采集时发 `0x2D`：`status = 0x03`，`detail = 0x0703`。这次不回 `0x0E`，参数不变。

## 采集中不要改这些

进行中再发下面的命令，ACK `status = 0x03`，`detail = 0x0703`，设备不执行：

- `0x19` 融合模式
- `0x1C` 开始六面校准
- `0x1D` 输出速率
- `0x1E` 启动配置（含量程）
- `0x27` 滤波档
- `0x2D` 恢复默认 VQF
- `0x2F` 设置零角速保持
- `0x31` 恢复零角速保持默认

查询可以继续，包括 `0x28`、`0x29`、`0x2C`、`0x2E`、`0x30`。取消用 `0x2B`。

`0x31` 仍是零角速保持恢复默认，不是这次的 VQF 恢复。VQF 恢复只用 `0x2D`。

## 重连

连上以后发空的 `0x2C` 和 `0x29`。不要假设一定是空闲。旧固件回未知命令时把整页收起来。`0x0B` 的能力字节仍然是滤波档个数，没有为这个功能新占一位。

## 和现有命令的关系

`0x1B` 仍然立刻失败，`detail = 0x0601`。不要用它触发这次的 60 秒初始化。

设备配置帧 `0x07` 仍是 28 字节。滤波配置 `0x0B` 仍是 16 字节。融合诊断 `0x0C` 仍是 60 字节。运动零偏 `0x09` 仍是 48 字节。零角速保持 `0x0F` 仍是 40 字节。设置记录版本仍是 8。

静置记录单独放在 `0x0803E000` 和 `0x0803F000`，不进陀螺零偏历史，也不进加速度校准区。

## 已烧录的镜像

SWD 4 MHz，只擦写应用区 `0x08008000`–`0x0801F004`，校验 94212 字节。SHA256 `9fe6c4a25b78335098a81d3280015a41f29724eee97a4d7bf5849aba41299c2d`。引导程序和 `0x0803C000` 之后的配置、校准原样保留。备份是 `artifacts/web-host/board-before-host-upgrade-20261002-190251.bin`。

发布体积：九轴 `text 93232 / data 976 / bss 12096`，六轴 `text 91264 / data 976 / bss 12096`。板上是九轴镜像。直方图大约占 2 KiB BSS。

烧录后 USB 回读，设置与烧录前备份里的最新记录一致，没有被这次烧录改写：

| 项 | 回读 |
| --- | --- |
| 融合模式 | 6 轴，已保存也是 6 轴 |
| 滤波档 | 0，已保存也是 0，能力字节 4 |
| 陀螺量程 | ±2000 °/s，已保存也是 ±2000 |
| 快速启动 | 关 |
| 开机采集 | 2000 ms |
| 输出 | 1000 Hz |
| 零角速保持阈值 | 仍是 0.30 / 0.70 °/s、0.15 m/s²、10 / 50 / 3 ms |

`0x2C` 回了 52 字节 `0x0E`：`source = 0`，`cal_valid = 0`。当前值和 `default_*` 都是初始 sigma 0.50、静止 sigma 0.035、陀螺门限 0.60、加速度门限 0.15。零偏约 +0.300 / +0.038 / −0.391 °/s，这是开机采集后 VQF 正在用的值。`0x29` 回了 28 字节 `0x0D`，状态空闲。运动零偏仍开着，`tauAcc` 为 1.0 s，与滤波档 0 一致。
