# 上位机交接：列出启动零偏历史

只读命令。不写 Flash，不改融合模式、滤波档、量程、输出或静置初始化。网页源码不用改，也不要部署。这版是 `20261002c`，已于 2026-10-02 用 4 MHz SWD 烧到板上。应用区 `0x08008000`–`0x0801F334`，校验 95028 字节，SHA256 `9b613764bfff58c6a87f34baece5b5e095b0674c16825da275167974e75a19b7`。USB 回读 `0x23` 得到 `20261002c`。空命令 `0x33` 回了 60 字节的 `0x34`：记录版本 3，36 条，序号 129，corrupt 为 0。再取偏移 3，序号仍是 129。旧固件不认识 `0x33`，会回 ACK `status = 0x01`。

## 查询

命令 `0x33`。成功时不回 ACK，只回消息 `0x34`，60 字节。采集静置初始化期间也允许查。

载荷可以是空，表示从最旧的一条开始。也可以是 2 字节小端 `offset`。`offset` 大于 50 回 ACK `status = 0x02`，不回历史帧。其它长度同样回 `0x02`。

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | uint8 | version，固定 1 |
| 1 | uint8 | record_version。0 没有记录，2 是旧的 15 条槽，3 是当前 50 条槽 |
| 2 | uint8 | corrupt。1 表示有一个槽存在但读不出来 |
| 3 | uint8 | count，有效条数，0 到 50 |
| 4 | uint16 | offset，本帧第一条的序号，0 是最旧 |
| 6 | uint8 | entry_count，本帧条数，0 到 3 |
| 7 | uint8 | reserved，固定 0 |
| 8 | uint32 | sequence，当前记录序号 |
| 12 | 3 条 | 每条 16 字节：bias_dps[3] float，temperature_c float |

零偏单位是 °/s，温度是 °C。只使用前 `entry_count` 条，后面的填 0。顺序是从旧到新。`count` 是全部条数，不是本帧条数。

没有记录时 `count = 0`、`record_version = 0`、`entry_count = 0`。`corrupt = 1` 且 `count > 0` 时，列出的是还能读的那一槽。

## 翻页

从 `offset = 0` 开始。下一次用 `offset + entry_count`。`entry_count = 0`，或 `offset + entry_count >= count` 时结束。两次回复的 `sequence` 不一样，说明中间又保存过，整表重读。

最多 50 条，每帧 3 条，所以最多 17 帧。这是开机采集写进 `0x0803E800` / `0x0803F800` 的历史，不是 `0x09` 运动零偏，也不是 `0x0E` 里的当前零偏。静置初始化的结果不会进这个表。
