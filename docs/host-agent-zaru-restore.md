# 上位机交接：零角速保持恢复默认值

这次固件增加一条命令，把零角速保持的六个阈值恢复成固件编译时的默认值。网页源码还没改，也不要部署。`0x31` 已随 2026-10-02 的静置初始化镜像烧到板上，应用区 SHA256 `9fe6c4a25b78335098a81d3280015a41f29724eee97a4d7bf5849aba41299c2d`。更早的板上固件不认识它。

不要改已保存的融合模式、滤波档、陀螺量程、输出速率和 CAN。恢复只替换零角速保持阈值。正在锁定的航向偏移不清除，下一拍开始用恢复后的阈值判断进出。

## 默认值

唯一来源是固件里的 `zaru_limits_default()`，对应这些宏：

| 字段 | 默认 |
| --- | --- |
| enter_dps | 0.30 |
| exit_dps | 0.70 |
| acc_dev_ms2 | 0.15 |
| enter_filter_ms | 10 |
| enter_confirm_ms | 50 |
| exit_confirm_ms | 3 |

上位机不要再写一份默认数。界面上的“恢复默认”只发这条命令，然后用回读的 `0x0F` 填显示。

允许范围、进入和退出的含义、六轴才锁定，仍以 `docs/host-agent-zaru-limits.md` 为准。`0x0F` 仍是 40 字节，`0x2E` / `0x2F` 的载荷不变。

## 协议

帧仍是 `AA 55`，CRC16-CCITT。小端。

旧固件收到 `0x31` 会回 ACK，`status = 0x01`（未知命令）。这时隐藏“恢复默认”，不要当成已经恢复。

必须先 `0x17` 进入设置模式。未进入时 `status = 0x03`。载荷不对时 `status = 0x02`。Flash 写入失败时 `status = 0x03`，运行中的阈值保持原值。

### 恢复 `0x31`

载荷固定 2 字节：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | uint8 | persist，0 或 1 |
| 1 | uint8 | 必须是 0 |

`persist = 0` 只改本次运行的阈值，断电后回到已保存值。`persist = 1` 把默认值写入 Flash。写入时模式、档位、量程、输出速率和 CAN 原样保留。

界面上的“恢复默认”发 `persist = 1`。

成功或失败后都会先回 ACK（`detail = 0`），再回一帧 `0x0F`。用 `0x0F` 确认：ACK `status = 0`，当前六个值等于上表；若 persist 为 1，已保存的六个值也要等于上表。超时保留界面上的原值，并提示未确认。

查询仍用空载荷的 `0x2E`。自定义阈值仍用 `0x2F`。
