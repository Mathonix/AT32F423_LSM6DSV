# 本轮代码检查与修复记录

本次范围：GCC 应用固件、用户 Bootloader、USB CDC 接收链路、设置持久化、Python 上位机和升级脚本。硬件相关验证使用主机模拟，不连接或烧录设备。

## 已修复

| 优先级 | 问题及触发条件 | 修复 |
|---|---|---|
| 高 | CDC 将主机 `wLength` 直接传入 8 字节控制缓冲区；请求方向错误也可能执行 SET_LINE_CODING | 严格校验长度、方向和接口；清除过期请求；保留 DTR/RTS 控制请求 |
| 高 | USB RX 依赖硬件包长直接复制，短缓冲区仍接收整包；FIFO 按字写入还可能覆盖尾部 | 保留真实缓冲区容量，拒绝超长包，排空 FIFO，逐字读取但只复制有效字节；拒绝非法端点索引和无效 SETUP |
| 高 | Bootloader 的向量检查使用宽松掩码，启动路径与升级结束路径检查不一致 | 统一 SRAM 范围、8 字节栈对齐和 Thumb 入口检查；END 额外限制入口位于已上传镜像内 |
| 高 | BEGIN/END 的总镜像长度被当作 DATA payload 长度，正常固件升级无法完成 | 保持 18 字节头不变，仅 DATA 等待 payload；对齐检查允许最后一包尾部不足一字 |
| 高 | 升级中或失败后可能被超时启动；BOOT 无实际启动作用；应用跳转时未恢复中断 | 跟踪本次会话的可启动状态，失败后不允许启动；完成 END 后处理 BOOT；切换 MSP 后用无栈汇编跳转并恢复中断 |
| 中 | RAM 启动标志与头文件不一致，地址未从链接器 RAM 分区中排除 | 统一到 `0x2000BFF0`，两个 GCC 镜像各保留顶部 16 字节；修正应用链接脚本依赖 |
| 中 | Bootloader 重用尚未完成 USB IN 发送的缓冲区 | 写入下一响应前等待完成，退出时给最终 ACK 有界等待时间 |
| 中 | 相同配置重复擦写 Flash；保存失败仍可能改变运行时 CAN ID | 相同持久化配置直接返回；先保存成功再更新运行时 ID |
| 中 | 升级脚本 BEGIN 未提供总长度、错误使用普通复位命令、未检查块对齐和镜像向量 | 修正两个升级入口、发送真正的 bootloader 命令、写入前校验、正确处理 ACK 分片和 CRC 错误 |
| 中 | Python 上位机混合解析把 ACK 字节当浮点数据；缺少六通道和多类消息解析；串口连接/断开生命周期不完整 | 单一混合流解析、有限缓冲区、CRC 重新同步、六通道映射、过滤非有限数值、后台连接及过期连接资源回收 |

## 回归验证

从仓库根目录运行：

```powershell
python -B tests/run_native.py
python -B -m unittest discover -s tests -p 'test_*.py' -v
python -B -m unittest discover -s tools/usb_host -p 'test_*.py' -v
mingw32-make -B -j4 SIX_AXIS=1 all
mingw32-make -B -j4 SIX_AXIS=0 all
mingw32-make -C bootloader -B -j4 all
```

`run_native.py` 在独立主机进程内映射模拟 Flash/USB 内存，不操作开发板。测试编译真实 C 实现，覆盖控制请求长度和方向、缓冲区哨兵、端点边界、CRC、升级状态、栈指针、重复配置写入，以及模拟 Flash 写失败后的旧记录回退。

Python 测试覆盖 ACK/JustFloat 任意分片、3/4/6 通道、错误 CRC、有限缓冲、连接取消和过期线程、升级报文、启动命令和完整模拟上传流程。

本轮执行结果：3 组原生 C 回归、40 项 Python 测试通过；六轴、九轴和 Bootloader 均通过强制全量构建，三个镜像的初始 SP 均为 `0x2000BFF0`。构建仍有条件编译下未使用变量/函数告警，以及 Bootloader 的 `nosys` 系统调用桩告警，未将其当成无告警构建。用户工作区现有的 Web 协议测试也已通过，但对应未提交文件未纳入本轮提交。

## 未解决的设计限制与实机验证

- **不是完整安全审计或安全启动方案。** USB/UART/CAN 维护接口缺少身份认证，CRC 不能验证固件发布者；有物理接口访问权者仍可修改参数或上传固件。
- **固件更新仍不具备跨复位的原子提交。** 本次防护阻止同一会话内启动失败镜像，但没有持久化 commit 标志或双镜像槽。升级断电后，启动阶段仍只检查向量，不能保证完整镜像通过 CRC。需要另行设计元数据分区与恢复策略。
- 重复相同配置不再擦写，但持续交替写入不同配置仍会消耗 Flash 寿命；未引入授权或限流策略。
- JustFloat 无长度和校验字段，噪声后的自动通道识别存在固有歧义；可靠性要求高时应使用带 CRC 的二进制协议。
- 当前修复以 GCC 构建为准，未同步验证归档 Keil 工程。部署时应配套更新 Bootloader 和应用。
- USB 枚举、USB/UART 实际完整升级、ACK 发完后的跳转、传感器/CAN 数据连续性、断电恢复仍须实机验收；不应将编译或模拟测试通过理解为实机验证通过。

本轮未改写或提交用户已有的 `tools/web_host` 未提交改动。
